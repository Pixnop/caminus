# Test houses

Seven WorldEdit schematics, one per thing Caminus does. Drop one on flat ground, stand inside, type
`/caminus temp`, press `K`. They are generated by `tests/Caminus.Scenarios/TemplateScenarios.cs` with
the game's own `BlockSchematic` serializer, so the files are byte-for-byte what `/we export` would
have written.

## Where the files go

WorldEdit reads and writes one flat folder, `sapi.GetOrCreateDataPath("WorldEdit")`, which is the
`WorldEdit` folder directly inside the installation data directory (`WorldEdit.ExportFolderPath` in
VSCreativeMod). There is no `schematics` subfolder. For the test profile that is:

```
~/.config/VSLInstallations/test-caminus/WorldEdit/
```

The seven files are already there. If you regenerate them, copy them again:

```bash
cp templates/*.json ~/.config/VSLInstallations/test-caminus/WorldEdit/
```

## Importing

`/we` needs creative mode and the `worldedit` privilege, both checked on every subcommand
(`WorldEdit.CanUseWorldEdit`). In a single player world, `/gamemode creative` is usually all it takes.

The import reads the workspace's start marker, and the marker is only computed once both ends of a
selection exist (`WorldEditWorkspace.UpdateSelection`). So mark the same spot twice:

```
/we tool -1          once per session: no tool selected, so the import uses the schematic's own replace mode
/we impr 0           once per session: no import rotation
/we s                mark start at your feet
/we e                mark end at your feet
/we imp cabin-stone  the .json is optional
```

With the default origin (`StartPos`), the schematic's north-west bottom corner lands on the block
your feet are in, and the house grows east (+X) and south (+Z). Stand on the ground and the floor
slab sits on the grass, not in it. Add `BottomCenter` as a second argument to centre the footprint
on yourself instead: `/we imp hall BottomCenter`.

**The two cellars go in with `TopCenter`.** That origin subtracts the full height, so the schematic's
top layer, the one holding the trapdoor, replaces the ground block you are standing on:

```
/we imp cellar TopCenter
```

You end up standing on the hatch. Open it and climb down.

Every file carries `ReplaceMode: ReplaceAll` (1). That matters: the format stores no air at all, so
any other mode would leave the interior full of whatever was there. ReplaceAll blanks the whole
bounding box first, which is also why importing into a hillside carves a clean hole. It is also why
`/we tool -1` is in the recipe above: with a tool selected, `PasteBlockData` uses the tool's replace
mode instead of the file's.

## What each one is for

### cabin-stone (5×9×5)

3×3×3 interior in granite cobblestone, oak door in the south wall, lit firepit in the middle, five
courses of chimney rising out of the roof right above it. The reference house. `/caminus temp` should
report `Sources: 4000 W`, a `Flue:` line with a real height and column count, and a room that climbs
well above the outside temperature.

### cabin-wood (5×5×5)

The same house in oak planks with a solid roof and no chimney at all. Two things to watch. Wood loses
less than stone, so at equal power it settles warmer, and with nowhere for the smoke to go the
`Smoke:` line climbs. Put it next to cabin-stone and read both.

### cabin-windows (5×9×5)

cabin-stone with two one-block holes at floor level in the north wall. Real air, no glass. They show
up in the `Openings:` breakdown, they feed the `draft ... m³/s` figure, and they make the chimney
actually pull: cold air low, warm air out the top. The `K` overlay paints them cyan.

### glass-house (5×5×5)

3×3×3 interior, stone floor, no fire. The four walls are leaded glass panes, `ns` on the north and
south sides and `ew` on the east and west ones, because `BlockGlassPane.GetRetention` only returns 1
across the pane's own plane. The roof is `glass-plain`, a full block: a pane has no horizontal plane,
so a pane roof would leak the room straight into the sky. Watch the `Sun:` line through a game day
and the room temperature following it.

### cellar (5×10×5)

3×3×3 stone room with a chest holding eight spelt loaves, a five-rung ladder shaft, and an airtight
trapdoor capping the top layer. Everything else in the box is solid rock, so it drops into the ground
as one piece. The ceiling ends up six blocks under the surface. Compare `Perish rate:` with the
`vanilla here:` figure printed next to it, and check `Ground node:` against the depth.

### cellar-lava (5×14×5)

The same cellar with four more layers underneath: a sealed 3×3×1 pocket of `lava-still-7`, three
blocks below the floor slab, rock on every side of it. The heat reaches the room through the stone,
so it lands in the `(nearby ... W)` part of the `Sources:` line rather than the main figure. Put it
next to a plain `cellar` and the perish rates should part company.

### hall (22×10×22)

20×4×20 interior, doors north and south, firepit and chimney in the middle. The vanilla room finder
gives up past 14 blocks, so anything this size only exists because of Caminus's own flood fill. If
`/caminus temp` answers with a `Volume 1600 blocks` line, the scanner did its job. It also makes the
stratification visible: `floor`, `eyes` and `ceiling` should be genuinely different in a room this
tall and this wide.

## Regenerating

```bash
export VINTAGE_STORY=$HOME/.config/VSLGameVersions/1.22.7
dotnet build -c Release
dotnet test tests/Caminus.Scenarios --no-build -c Release --filter "FullyQualifiedName~TemplateScenarios"
```

Each scenario builds its house in mid-air in a scratch world, exports the box, writes the file here,
then re-imports it 30 blocks higher and checks the blocks and the block entity data came back. The
firepit still burning and the bread still in the chest after that round trip is the part worth having.
